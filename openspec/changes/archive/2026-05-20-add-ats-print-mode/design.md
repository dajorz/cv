## Context

The existing CV is a single-page static site with a two-column visual layout (sidebar + main), iconography, color, and a committed static PDF (`CV - Daniel Jordan.pdf`). ATS parsers commonly mangle this format. Project conventions forbid build tooling, package managers, and JS frameworks. Bilingual parity (ES/EN) is mandatory.

## Goals / Non-Goals

**Goals:**
- Produce an ATS-friendly PDF that is text-based, single column, plain typography, black-on-white, with no icons or tables.
- Add the capability with **zero new tooling and zero content duplication**.
- Inherit the active language from the existing toggle (no new language UI).
- Preserve the current visual print stylesheet and the existing static visual PDF.

**Non-Goals:**
- Generating `.docx` or any non-PDF format.
- One-click silent download (using the browser's print dialog is acceptable).
- A second HTML page or any duplication of CV content.
- Server-side rendering or any backend.

## Decisions

### D1 — Print mode toggle on `index.html`, not a separate `ats.html`

Activate ATS rendering via a body class (`body.ats-print`) combined with the existing `@media print`, instead of duplicating the CV in a second HTML file.

**Alternatives considered:**
- *Separate `ats.html`*: would duplicate all CV content → drift between visual and ATS versions every time copy changes (and bilingual parity doubles the cost).
- *Static pre-generated PDF*: would need to be regenerated by hand every edit; high risk of stale ATS PDF.
- *Markdown source + build script (`md-to-pdf`)*: violates the "no build tooling, no package manager" convention.

**Rationale:** single source of truth (the DOM), zero new dependencies, automatic bilingual parity via the existing toggle.

### D2 — Filename via transient `document.title` swap

On click, JS stores the current title, sets `document.title` to `CV-Daniel-Jordan-ATS-<lang>` (where `<lang>` is `ES` or `EN`), then calls `window.print()`. On `afterprint`, restore the original title and remove the body class.

**Alternatives considered:**
- *Server-generated download with `Content-Disposition`*: requires a backend → out of scope.
- *Leaving the default title*: produces a non-descriptive filename suggestion such as "Daniel Jordan - Senior Software Engineer.pdf".

**Rationale:** Chromium and Firefox derive the suggested filename from `document.title`. The user can still override. Acceptable trade-off.

### D3 — New `@media print` rules scoped to `body.ats-print`

Add a dedicated `@media print` block that only applies when `body.ats-print` is set. The existing print stylesheet remains untouched and continues to govern the regular Ctrl+P flow.

**Rationale:** non-invasive, preserves existing print behavior, easy to review and revert.

### D4 — Inherit language from existing toggle

The ATS button reads the current language state (the existing class on `<body>` or whatever the toggle controls) and uses it to choose the filename suffix and the language span visibility (which already works automatically).

**Rationale:** zero new UI; one less decision for the user; consistent with the rest of the site.

### D5 — Button placement and label

Add a second fixed-position action button next to the existing "Download PDF" button, with bilingual label (`ATS PDF` for both EN and ES — the term is widely understood and the same in both languages). Reuse the existing `.pdf-download-btn` class plus an `--ats` modifier for positioning.

**Rationale:** discoverability and consistency with the existing visual pattern; minimal UI surface.

### D6 — Tech tags rendered as plain inline text in ATS mode

`.tech-tags` currently render as styled pill-like elements. In ATS mode they become an inline plain-text line (e.g. `Tech: Azure, .NET, Kubernetes`) so ATS parsers extract them as part of the experience description.

**Rationale:** ATS parsers struggle with floated/inline-block "tag" widgets; plain text is robust.

## Risks / Trade-offs

- **[Filename override may not stick]** → Some browsers (older Safari) ignore mid-flight `document.title` changes for the print dialog suggestion. *Mitigation:* the suggested filename is still acceptable from the existing title; the swap is best-effort.
- **[`afterprint` may not fire if the user dismisses the dialog quickly]** → Body class and title could remain swapped. *Mitigation:* also call cleanup from a `setTimeout` fallback (e.g. 60s) and from a `beforeprint`/`afterprint` pair on `window.matchMedia('print')` where available.
- **[Default browser print headers/footers may show URL and date]** → That's user-controlled in the print dialog; document in README/manual that users should uncheck "Headers and footers" for cleanest output.
- **[Mobile browsers' print is inconsistent]** → ATS PDFs are typically generated on desktop. The button still works on mobile; output quality is best-effort.
- **[Page breaks in long experience lists]** → Add `page-break-inside: avoid` on `.experience-item` headers to prevent orphaned dates; leave bullet lists to break naturally.
